Key Findings from Data Exploration
1. Demand grew from ~1,467 MW to ~3,750 MW across 8 years — that is a 12.4% CAGR. The distribution of load today is fundamentally not the distribution from 5 years ago.
2. Electrification is accelerating: Ghana rural electricity access rose from 67.2% (2018) to ~83% (2026 est.). Hundreds of thousands of new households connect each year with unknown load profiles, changing aggregate load shape in ways a pure time-series model cannot anticipate.
3. The hidden factor: We lack data on electrification rates, GDP growth, urbanisation, and industrial activity — all of which drive load. The model absorbs these into the trend implicitly, but they remain invisible confounders.
The Consequence for Modelling
European and North American grids have 0–1% annual demand growth with stable distributions. Models trained on 5-year-old data still perform well. In West Africa, stationary load distributions cannot be assumed — last year's patterns are not this year's. Blindly importing architectures from mature grids risks models that degrade rapidly as the grid evolves.

02 / Current Practice Understanding the operator's existing workflow
Operator Context
GridCo's Current Approach: From
Heuristics to Data-Driven.
The Existing Workflow
  • Dispatchers use a semi-manual workflow built around Excel spreadsheets
  • They find a similar historical day by experience, adjust for temperature differences, and manually populate the dispatch schedule
  • This "similar-day" heuristic is not bad — experienced operators with domain knowledge produce reasonable forecasts
  • However, the process is slow (~45 minutes) per forecast cycle
Systematic Limitations
  • Cannot detect patterns that play out over weeks or seasons
  • Does not learn from accumulated historical data (70k+ hours unused)
  • No systematic way to improve from past errors — each forecast is a fresh start
  • Manual process takes ~45 minutes — time that could be spent on higher-level decisions
What We Validated
  • We digitised GridCo's similar-day approach as a KNN model
  • KNN achieved 141 MW MAE — objectively worse than a simple 2-day weighted trend (113 MW MAE)
  • Confirmed: data-driven methods can outperform human heuristics when given enough historical data
  • Our goal: provide a more accurate automated forecast to complement GridCo's workflow, not replace the operator

03 / Foundations Understanding the data before building models
Data Exploration
Initial Work: Understanding Patterns
Before Machine Learning.
Patterns We Found in the Data
Strong daily seasonality — morning ramp (6–10h), evening peak (17–21h), overnight trough
Clear weekly cycle — weekends consistently lower than weekdays
Monthly variation — dry season vs wet season demand patterns
Growth trend — visible across all years (~12.4% CAGR)
What stands out: Temperature correlates with load but its effect is largely captured by hour-of-day and month-of-year features already. It is slow-moving and collinear with cyclical features — isolating it adds little predictive value while introducing weather forecast uncertainty.
Starting Simple — Resisting Complexity
We deliberately avoided jumping to deep learning. Many forecasting projects suffer from the "illusion of complexity" — assuming difficult problems require sophisticated models before understanding the data.
First Model
Classical Decomposition
Trend + Seasonality · ~3–4% MAPE
Second Model

Key insight: These simple models already achieved reasonable accuracy. This confirmed the problem was solvable without excessive complexity. The underlying load structure is strong enough that basic decomposition captures most of the signal.
Our philosophy: Before applying any machine learning, study what the data itself can tell you. Establish a strong simple baseline. If a classical decomposition achieves 3–4% MAPE, the marginal value of deep learning needs to be proven — not assumed. This discipline prevented us from over-engineering a solution to what turned out to be a fundamentally pattern-rich forecasting problem.

Why Decomposition Linear Wins
The Decomposition Linear model (DLinear) continuously decomposes load into two components:
  • Trend component: captures the gradual direction of load (growth or decline over days/weeks)
  • Seasonal component: captures the repeating daily and weekly pattern (morning ramp, evening peak)
  • Each component gets a simple learned weight, plus calendar information (hour, day-of-week, month)
  • These weighted parts sum to the final forecast — no attention, no recurrence, no convolutions
Why it works: The underlying load patterns may not be complex enough to benefit from deeper architectures. DLinear's simplicity (~36K parameters vs 1–2M for the others) means it captures signal while deeper models fit noise and spurious correlations. It trains on a laptop CPU in minutes.

Why Both MAE and MAPE Matter
MAE (Mean Absolute Error): average error in megawatts — the operational metric GridCo dispatchers care about because they dispatch power in MW units.
MAPE (Mean Absolute Percentage Error): error as a percentage of actual load — useful for comparing accuracy across different load levels (e.g., 121 MW error is ~3.9% at peak but a larger percentage at low load).
Both are reported because each tells a different part of the story. MAE answers "how many MW of reserve must we hold?" MAPE answers "how reliable is our forecast relative to the load level?"
The 2024 spike (226 MW) shows how regime shifts disrupt models. F4 tested on COVID recovery — the growth discontinuity caused errors to double. This is exactly why 6-fold CV is essential: one number hides regime-dependent failure.

06 / Correction Learning from residual errors to push further
Residual Analysis
Pushing Further: Learning from Prediction Errors.
The Discovery: Errors Are Not Random
Even after achieving good raw DLinear results, we studied the residuals — the errors between predicted and actual load. Normally, a good model's errors should be random noise. Instead, we found serial correlation ρ = 0.79 between consecutive hours (hour t → t+1). This means: if DLinear was wrong by +X MW at hour 0, it is likely wrong in the same direction at hour 1.
Why this matters: These residuals are learnable — we can train a second-stage model to predict the error and subtract it from the forecast. This is the principle behind all error correction approaches.
TIDE — Trend-Adjusted Iterative
Debiasing Engine
A zero-parameter filter that dampens recent errors using an exponentially weighted moving average. Think of it as a smart smoothing filter that learns how much to trust the latest error vs. the long-term average.
95.5 MW · −20.9% improvement
ARDRegression — Probabilistic
Correction
A Bayesian linear model trained on calendar features (hour, day-of-week, month, temperature) to predict the error. Learns persistent bias patterns — e.g., "DLinear consistently overpredicts Tuesday 19h by 15 MW."
Batch mode: no improvement
Sequential: 68.9 MW · −40.4%
The Critical Finding
TIDE's 20.9% improvement comes from one thing: access to recent error history. ARDRegression with the same features but no error history adds nothing. This means the dominant error signal is time-based autocorrelation, not weather or calendar patterns.
The streaming opportunity: A streaming architecture — correcting forecast hour-by-hour as actuals arrive — could unlock the full 40% error correction potential in production, using the serial correlation that batch models cannot exploit.
Summary of error correction methods tested: TIDE (−20.9%), SMA-7d (−8.3%), Kalman filter (−15.2%), ARD batch (−0.5%), ARD sequential (−40.4%). The sequential result reveals what is possible when a model sees each true error as it happens — a lightweight DLinear with continuous real-time correction may be the most practical path forward for grids like ours.
TIDE = Trend-adjusted Iterative Debiasing Engine · ARD = Automatic Relevance Determination
